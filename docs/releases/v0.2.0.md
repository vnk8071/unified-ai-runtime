# UAIRT 0.2.0: language models, speech, a C++17 core and Windows ARM64

One C API to run compiled AI models on QNN (Qualcomm NPUs), ONNX Runtime, TFLite, CoreML, TensorRT, OpenVINO, NCNN, ExecuTorch, llama.cpp,
whisper.cpp and language model servers. Write the application once; choose the backend by name when you create an engine. Backends are plugins behind
an append-only C ABI. Pre-1.0: the API and ABI may change.

```bash
pip install "uairt[onnxruntime]"      # Linux x86_64 and aarch64, macOS arm64, Windows x64 and ARM64; Python 3.9 and later
```

## What is new since 0.1.0

- **Language models and speech.** New backends for **llama.cpp** (GGUF: tokenize, sessions, logits, text completion; `device` picks a llama.cpp device such as
  `CUDA0`, `Vulkan0`, `GPUOpenCL` or the Hexagon NPU as `HTP0`), **whisper.cpp** (speech to text), **ExecuTorch** (`.pte`) and **llmserver** (attach to
  Ollama, LM Studio or SGLang over HTTP).
- **`libuairt_llm`.** Sampling (temperature, top-k, top-p, seed) and a streaming generation loop over the session API, for any backend that has sessions. It stops where the
  model ends its text, like llama.cpp's own tools. C, C++, Python and Rust examples are under `examples/`.
- **A C++17 core with no C++ runtime.** The core is built without exceptions, RTTI or the STL, so `libuairt` still needs no C++ runtime and exports exactly the C API.
  Plugins stay C or C++ as they like and never link the core.
- **Windows ARM64 wheel**, plus the Linux, macOS and Windows x64 wheels. QNN, NCNN and llama.cpp have run on a Snapdragon X Elite laptop.
- **Android and iOS.** The NDK build (`cmake --preset android-arm64`) and example apps for both: a detector on a picture and a live camera detector. QNN, TFLite and llama.cpp
  ran on a Qualcomm SM8850 board; CoreML ran on an iPhone 12.
- **For people and for coding agents.** `scripts/doctor.sh` checks installed vendor SDK versions against the tested and minimum ones, and `docs/agents/` has
  playbooks for running a model on a device, exporting a model, writing application code, and preparing inputs and decoding outputs.
  `scripts/export_model.py` converts a PyTorch or ONNX model to a backend's format and checks the result through UAIRT.

The full list is in [CHANGELOG.md](../../CHANGELOG.md).

## What was verified, and what was not

"Verified" means a real model ran through the backend on the named hardware and matched the vendor's own tool.

| Backend | Verified on |
|---|---|
| QNN | QCS6490, QCS8550, a Snapdragon X Elite laptop and an SM8850 board; byte-identical to `qnn-net-run` |
| ONNX Runtime | macOS arm64 (CPU) and a GTX 1650 (CUDA provider); matches Python ONNX Runtime |
| TensorRT | GTX 1650 and a Colab Tesla T4; bit-identical to TensorRT's Python API |
| CoreML | Apple M5 (identical to CoreML itself) and an iPhone 12 |
| llama.cpp | Apple M5 (Metal), Ubuntu with an RTX 3060 (CUDA and Vulkan), Snapdragon X Elite, an SM8850 board; greedy output equals `llama-completion` (GPU and NPU text can differ from the CPU's after a few tokens) |
| OpenVINO, NCNN, TFLite, whisper.cpp, ExecuTorch | see the table in the [README](../../README.md#status) |

Not verified: any backend or device not named in the README table. The Linux, macOS and Windows x64 wheels are built and tested by CI; they were not each run by hand on every platform. A passing `ctest` with only the reference backend
proves the core, loader and bindings, not a vendor runtime.

## Known limitations

- Static shapes only, one graph per QNN model, host memory (plus DMABUF and pinned buffers where a backend supports them), no asynchronous execution.
- A DLC on the QNN HTP backend crashes in Qualcomm's `libQnnHtpPrepare.so` on the QCS6490 (Hexagon v68) with QAIRT 2.46.0.260424, including with the SDK's own `qnn-net-run`;
  context binaries work there. The TFLite QNN delegate crashes the same way on v68.
- ONNX Runtime's plugin execution providers depend on its device discovery, which did not find the NPU on a Linux QCS6490 board.
- Only the ONNX Runtime plugin is in the wheels. QNN, TensorRT, CoreML and the other backends need their vendor runtimes, so build their plugins from source
  (see `docs/backends/`) and put them on `UAIRT_PLUGIN_PATH`. Vendor SDKs are never part of this repository.

## Compatibility

The public headers are append-only: this release appends `is_end_of_generation` to the end of the session table and adds `uairt_model_is_end_of_generation`; nothing existing changed.
Python 3.9 and later; ONNX Runtime 1.22 or newer for the wheel's plugin.

Please open an issue with the output of `scripts/doctor.sh` when something does not run.
